# Sensor AR — แอป Android สำหรับดูค่าเซนเซอร์แบบ AR

ส่องกล้องไปที่ **ArUco marker** ที่ติดไว้หน้างาน แล้วค่าเซนเซอร์ของอุปกรณ์นั้นจะเด้งขึ้นมา
เป็นหน้าต่างข้อความลอยอยู่เหนือ marker อัปเดตเรียลไทม์จาก Weather Dashboard ตัวเดียวกับที่เปิดบนเว็บ

```
กล้องมือถือ ──▶ ARCore (ภาพ + ค่าเลนส์) ──▶ OpenCV ArUco ──▶ ตำแหน่ง marker บนจอ
                                                                │
Dashboard ──▶ /api/sensors/snapshot (ค่าย้อนหลัง) ──────────────┤──▶ popup ข้อความ
           └─▶ /api/stream (SSE ค่าใหม่ทุกครั้ง) ───────────────┘
```

marker เป็น ArUco พจนานุกรม `DICT_4X4_50` อ่านด้วย OpenCV ไม่ได้ใช้ Augmented Images ของ ARCore
(ArUco มีรายละเอียดน้อยเกินกว่าที่ ARCore จะรับเข้าฐานข้อมูลรูป) ARCore เหลือหน้าที่แค่
ส่งภาพจากกล้อง ค่าพารามิเตอร์เลนส์ และแปลงพิกัดภาพเป็นพิกัดจอให้

## สิ่งที่ต้องมี

| อย่าง | รายละเอียด |
| --- | --- |
| Android Studio | Ladybug (2024.2) ขึ้นไป พร้อม JDK 17 |
| มือถือ Android | Android 7.0+ **และรองรับ ARCore** — ดูรายชื่อที่ [ARCore supported devices](https://developers.google.com/ar/devices) |
| Google Play Services for AR | แอปจะชวนติดตั้งให้เองตอนเปิดครั้งแรก |
| Weather Dashboard | รันอยู่และเข้าถึงได้จาก Wi-Fi วงเดียวกับมือถือ |

OpenCV มาเป็น dependency ปกติ (`org.opencv:opencv`) ไม่ต้องติดตั้ง SDK แยก แต่ทำให้ APK
ใหญ่ขึ้นราว 36 MB เพราะแบก native library สองสถาปัตยกรรม ถ้าอยากได้ไฟล์เล็กลงให้ build
เป็น App Bundle หรือตัดเหลือ `arm64-v8a` อย่างเดียวใน `ndk { abiFilters }`

> อีมูเลเตอร์ใช้ได้แต่ต้องตั้งค่า AVD ให้รองรับ AR (Play Store image + เปิด camera "VirtualScene")
> แล้วเอารูป marker ไปแปะในฉากจำลอง ซึ่งยุ่งกว่าการทดสอบด้วยเครื่องจริงพอสมควร

## เริ่มใช้งาน

### 1. เปิด dashboard ให้มือถือเข้าถึงได้

```bash
npm run dev                          # ที่โฟลเดอร์โปรเจคหลัก
npm run simulator -- --devices 6     # ตัวจำลองส่งค่า dev-A..dev-F ครบทุก marker
```

ตัวจำลองส่งแค่ `dev-A` กับ `dev-B` ถ้าไม่ใส่ `--devices 6` — marker ที่เหลือจะขึ้นว่า "ยังไม่มีข้อมูล"

หาที่อยู่ IP ของเครื่องที่รัน dashboard (ฝั่ง Windows ใช้ `ipconfig` ดู IPv4 Address)
แล้วลองเปิด `http://<IP>:3000` จากเบราว์เซอร์ในมือถือ ถ้าเปิดไม่ขึ้นให้ตรวจ Windows Firewall
ว่าอนุญาต Node.js ที่พอร์ต 3000 หรือยัง

### 2. build แล้วติดตั้งลงมือถือ

เสียบสาย USB เปิด **Developer options → USB debugging** ในมือถือ แล้วสั่ง

```bat
android-ar\build-install.bat
```

สคริปต์จะ build APK, ติดตั้งลงเครื่องที่ต่ออยู่, เปิดอุโมงค์ USB และเปิดแอปให้เสร็จในคำสั่งเดียว
กำหนดที่อยู่ dashboard ใหม่ได้ด้วยการใส่ต่อท้าย

```bat
android-ar\build-install.bat http://10.9.139.89:3000
```

> สคริปต์ตั้ง `GRADLE_USER_HOME` ไว้ที่ `D:\Android\gradle-home` เพราะไดรฟ์ C: ของเครื่องนี้เหลือพื้นที่น้อย
> ถ้า build จาก Android Studio แทน cache จะไปลงที่โฮมของผู้ใช้บนไดรฟ์ C: ซึ่งกินอีก 1-2 GB

จะสั่ง Gradle ตรง ๆ ก็ได้ (SDK อ่านจาก `local.properties` อยู่แล้ว)

```bat
set GRADLE_USER_HOME=D:\Android\gradle-home
android-ar\gradlew.bat -p android-ar :app:assembleDebug -PdashboardUrl=http://10.9.139.89:3000
```

ไฟล์ APK ที่ได้อยู่ที่ `android-ar/app/build/outputs/apk/debug/app-debug.apk` (~18 MB)
ก๊อปไปติดตั้งในเครื่องอื่นได้ (ต้องอนุญาต "ติดตั้งจากแหล่งที่ไม่รู้จัก")

### สภาพแวดล้อมที่ติดตั้งไว้บนเครื่องนี้แล้ว

| อย่าง | ที่อยู่ |
| --- | --- |
| Android SDK (platform 35, build-tools 35 + 34, platform-tools) | `D:\Android\sdk` |
| Gradle 8.9 | `D:\Android\gradle-8.9` + cache ที่ `D:\Android\gradle-home` |
| JDK 17 | `C:\Program Files\Microsoft\jdk-17.0.19.10-hotspot` |
| adb | `D:\Android\sdk\platform-tools\adb.exe` |

รวมประมาณ 2.5 GB ทั้งหมดอยู่บนไดรฟ์ D: ไม่กินพื้นที่ C:

### มือถืออยู่คนละวง Wi-Fi กับคอม

ใช้อุโมงค์ผ่านสาย USB แทน — มือถือจะเรียก `http://localhost:3000` แล้ววิ่งมาที่คอม

```bat
D:\Android\sdk\platform-tools\adb.exe reverse tcp:3000 tcp:3000
```

แล้วตั้งที่อยู่ในแอปเป็น `http://localhost:3000` (กดค้างที่แถบสถานะ → ที่อยู่ Dashboard)
วิธีนี้ใช้ได้ตลอดเวลาที่เสียบสายอยู่ ไม่ต้องสนใจว่าเน็ตวงไหน

### 3. พิมพ์ marker

รูปอยู่ที่ [`ar-markers/`](../ar-markers/) พิมพ์บนกระดาษด้าน **ขนาดไหนก็ได้**
(ใหญ่ขึ้น = ส่องได้ไกลขึ้น) ขอแค่อย่าให้ขอบขาวรอบ ๆ ถูกตัด
แล้วติดไว้ตรงจุดที่วางเซนเซอร์จริง — `dev-A.png` ติดที่อุปกรณ์ `dev-A`

### 4. ส่องกล้อง

เปิดแอป อนุญาตให้ใช้กล้อง แล้วเล็งไปที่ marker
popup ขึ้นทันทีที่อ่านรหัสได้ **แตะที่ popup** เพื่อกางดูค่าทุกตัวพร้อมกราฟย่อและสถิติ

## หน้าตาของหน้าต่าง AR

ส่องเจอ marker แล้วจะมีหน้าต่างลอยขึ้นสามใบ — **วิดีโอ / ข้อมูลจุดติดตั้ง / ค่าเซนเซอร์**
โดยใบค่าเซนเซอร์อยู่ล่างสุดติดกับรูปเพราะเป็นใบที่ต้องอ่านบ่อยที่สุด

- **ใบค่าเซนเซอร์** — ค่าสำคัญ 3 ค่า (ค่าที่เกินเกณฑ์ถูกดันขึ้นก่อนเสมอ)
  แตะเพื่อกางดูครบทุก metric พร้อมกราฟเส้นย้อนหลัง ค่าเฉลี่ย/ต่ำสุด/สูงสุด และเกณฑ์เตือน
- **ใบข้อมูล** — ข้อความจาก `ar-content/info/<device>.txt` เลื่อนอ่านได้
- **ใบวิดีโอ** — คลิปจาก `ar-content/video/<device>/` เล่นวน ปิดเสียงไว้ มีปุ่มลำโพง
- เห็นหลาย marker พร้อมกัน จะกางครบสามใบเฉพาะจุดที่ใกล้ที่สุด จุดอื่นเหลือใบค่าเซนเซอร์
  แตะที่ใบนั้นเพื่อย้ายโฟกัส

### marker ชนิดประวัติ

marker ที่ตั้ง `"kind": "history"` ใน `markers.json` เป็นจุดเล่าเรื่องพื้นที่ ไม่ผูกกับเซนเซอร์

- **มุมมอง 360°** — คลิป equirectangular ฉายลงทรงกลม ลากนิ้วบนภาพเพื่อหันมองรอบตัว
  (ใช้ `SphericalGLSurfaceView` ของ media3 ซึ่งรับทั้งการลากนิ้วและการเอียงเครื่อง)
- **ประวัติพื้นที่** — กดปุ่ม "ดูประวัติ" แล้วหน้าต่างจะกางไปอยู่ข้าง ๆ คลิป
  เนื้อหาแทรกรูปภาพได้ด้วยรูปแบบ `![คำบรรยาย](ชื่อไฟล์.jpg)`
- ไม่มีหน้าต่างค่าเซนเซอร์
- จุดสีที่หัวหน้าต่าง: เขียว = ปกติ, แดง = มีค่าหลุดเกณฑ์, เหลือง = ข้อมูลค้างเกิน 1 นาที, เทา = ยังไม่มีข้อมูล
- หน้าต่างจะจางลงเมื่อเฟรมนั้นอ่าน marker ไม่ได้ และหายไปภายใน ~0.5 วินาทีถ้ายังอ่านไม่ได้อีก

> ArUco อ่านใหม่ทุกเฟรม ไม่มีการจำตำแหน่งเก่าแบบ Augmented Images ดังนั้น marker ที่เอาออกไป
> จากเฟรมแล้ว popup จะหายตามทันที ที่ต้องหน่วงไว้ครึ่งวินาทีก็เพื่อกันกะพริบตอนภาพเบลอหรือ
> แสงแวบเดียว ปรับได้ที่ `STALE_MARKER_GRACE_NANOS`

เกณฑ์เตือนดึงมาจาก `ALERT_*` ใน `.env` ของ dashboard โดยตรง ไม่ต้องตั้งซ้ำในแอป

## หน้าตั้งค่า — เปิดด้วยการกดค้าง

แถบด้านบนมีแค่สถานะการเชื่อมต่อ จำนวน marker ที่เห็น ปุ่มส่งความเห็น และปุ่มสลับภาษา
**ไม่มีปุ่มเฟือง** เพราะหน้างานมีคนทั่วไปหยิบเครื่องไปส่องเอง ถ้ามีปุ่มโผล่อยู่ก็มีคน
กดเข้าไปแก้ที่อยู่เซิร์ฟเวอร์จนแอปใช้ไม่ได้

เจ้าหน้าที่เข้าหน้าตั้งค่าได้ด้วยการ **กดค้างที่แถบสถานะ** (ป้ายซ้ายบนที่บอกว่าเชื่อมต่อแล้ว)
ประมาณ 2 วินาที ในนั้นยังมีครบเหมือนเดิม — ที่อยู่ dashboard พร้อมปุ่มทดสอบ ภาษา
รายการ marker ที่ผูกไว้ และรายการที่ใช้ไม่ได้

ส่วนการสลับภาษาไทย–อังกฤษ ย้ายออกมาไว้บนแถบด้านบนแล้ว ผู้ชมจึงเปลี่ยนเองได้
โดยไม่ต้องเข้าหน้าตั้งค่า

## ข้อมูลและวิดีโอในหน้าต่าง

เนื้อหาที่โผล่ตอนกาง popup อยู่ที่ [`ar-content/`](../ar-content/) แยกตามอุปกรณ์

```
ar-content/info/dev-A.txt              ข้อมูลข้อความ (ชื่อไฟล์ = deviceId)
ar-content/info/dev-A.en.txt           ฉบับภาษาอังกฤษ ไม่มีก็ใช้ไฟล์ไทยแทน
ar-content/video/dev-A/clip.mp4        คลิปของ dev-A (ชื่อโฟลเดอร์ = deviceId)
ar-content/video360/site-1/pano.mp4    คลิป 360 องศาของ marker ชนิดประวัติ
ar-content/history/site-1/history.txt  ประวัติพื้นที่ แทรกรูปในโฟลเดอร์เดียวกันได้
```

ใส่คลิปที่ความละเอียดไม่เกิน 1080p เพราะถอดรหัสด้วยฮาร์ดแวร์ของมือถือ
ถ้าเครื่องเล่นไม่ได้ popup จะขึ้นข้อความเตือนแทนจอดำ รายละเอียดทั้งหมดอยู่ใน
[`ar-content/README.md`](../ar-content/README.md)

## ผูกหมายเลข marker กับอุปกรณ์

อยู่ในไฟล์เดียว — [`ar-markers/markers.json`](../ar-markers/markers.json)

```json
{ "image": "dev-A.png", "arucoId": 0, "deviceId": "dev-A", "label": "dev-A", "location": "Zone A" }
```

`arucoId` คือหมายเลขที่กล้องอ่านได้ (0-49 ห้ามซ้ำ) ส่วน `image` เป็นแค่ไฟล์สำหรับพิมพ์
`deviceId` ต้องตรงกับ id ใน `data/devices.json` ของ dashboard (topic `sensors/<deviceId>/data`)
วิธีเพิ่มรูปใหม่ดูที่ [`ar-markers/README.md`](../ar-markers/README.md)

โฟลเดอร์ `ar-markers/` ถูกประกาศเป็น assets ของแอปใน `app/build.gradle.kts`

```kotlin
sourceSets.getByName("main").assets.srcDir("../../ar-markers")
```

จึงไม่มีการคัดลอกรูปซ้ำสองที่ — แก้ที่เดียวแล้ว build ใหม่

## โครงสร้างโค้ด

```
app/src/main/java/com/weatherdashboard/ar/
├── MainActivity.kt              ประกอบทุกส่วนเข้าด้วยกัน
├── ar/
│   ├── ArSessionController.kt   ARCore session + แปลงมุม marker เป็นพิกัดบนจอ
│   ├── ArucoScanner.kt          ถอดรหัส ArUco ด้วย OpenCV + หาระยะด้วย solvePnP
│   ├── BackgroundRenderer.kt    วาดภาพจากกล้องด้วย OpenGL ES 2
│   ├── DisplayRotationHelper.kt แจ้ง ARCore เมื่อจอหมุน
│   └── MarkerCatalog.kt         อ่าน markers.json + ตรวจ arucoId ซ้ำ/เกินช่วง
├── data/
│   ├── DashboardClient.kt       REST + ตัวอ่าน SSE
│   ├── DeviceContent.kt         อ่านข้อความ/ประวัติ/คลิปของแต่ละจุดจาก ar-content/
│   ├── SensorRepository.kt      รวมค่าล่าสุดแยกรายอุปกรณ์ + reconnect อัตโนมัติ
│   ├── UsageTracker.kt          นับการสแกนรายจุด/เวลาใช้งาน + ส่ง feedback
│   ├── UsageQueue.kt            คิวในเครื่อง กันข้อมูลหายตอนหลุด Wi-Fi
│   ├── Models.kt                metric, เกณฑ์เตือน, รูปแบบ JSON ของ dashboard
│   └── Prefs.kt                 ที่อยู่เซิร์ฟเวอร์ ภาษา installId และสถานะ feedback
├── i18n/Strings.kt              ข้อความไทย/อังกฤษ (สลับได้ทันทีในแอป)
└── ui/                          Compose ทั้งหมด — popup, แถบสถานะ, หน้าตั้งค่า
```

จุดที่ควรรู้: **ไม่ได้ใช้ Sceneform หรือ Filament** เพราะสิ่งที่ต้องแสดงคือหน้าต่างข้อความล้วน ๆ
โค้ดเอามุมทั้งสี่ที่ OpenCV อ่านได้ (พิกัดภาพกล้อง) ส่งเข้า `frame.transformCoordinates2d()`
ให้ ARCore แปลงเป็นพิกัดบนจอ — จัดการเรื่องจอหมุนกับการ crop ภาพให้เต็มจอให้เอง —
แล้ววาง Compose popup ทับตรงนั้น ได้ข้อความคมชัดตามระบบ รองรับภาษาไทยเต็มรูปแบบ
ส่วนระยะห่างมาจาก `solvePnP` แบบ `IPPE_SQUARE` ซึ่งคิดมาสำหรับ marker สี่เหลี่ยมจัตุรัสโดยเฉพาะ

## สถิติการใช้งานและ feedback

แอปเก็บให้เองโดยผู้ใช้ไม่ต้องทำอะไร แล้วส่งขึ้น dashboard เป็นชุด:

| เก็บอะไร | นับยังไง |
| --- | --- |
| สแกนจุดไหน กี่ครั้ง | marker ต้องอยู่ในเฟรมต่อเนื่อง 0.8 วินาทีขึ้นไปถึงนับหนึ่งครั้ง กวาดกล้องผ่านเฉย ๆ ไม่นับ |
| ดูจุดนั้นนานแค่ไหน | จับเวลาตั้งแต่เห็นจนหายไปจากเฟรมเกิน 6 วินาที หายแวบเดียวเพราะมือสั่นยังนับเป็นครั้งเดิม |
| ใช้งานแอปนานแค่ไหน | นับเฉพาะตอนแอปอยู่หน้าจอจริง สลับออกไปแอปอื่นไม่เกิน 2 นาทีแล้วกลับมา ยังถือเป็นรอบเดิม |
| กี่เครื่อง | `installId` สุ่มตอนติดตั้งครั้งแรก ไม่ได้อ่านหมายเลขเครื่องและไม่ผูกกับตัวบุคคล ลบแอปแล้วหายไปด้วย |

ส่ง feedback ได้สองทาง ทั้งคู่เป็น **ในแอป ไม่ต้องสแกน marker แยก**:

1. ปุ่มรูปกระดาษกับปากกาบนแถบด้านบน (อยู่ข้างปุ่มสลับภาษา) กดได้ตลอดเวลา
2. แอปชวนเองครั้งเดียว หลังผู้ใช้ดูมาแล้วอย่างน้อย 2 จุด หรืออยู่กับแอปเกิน 90 วินาที
   ถ้ากด "ไว้ก่อน" จะไม่ชวนอีกภายใน 7 วัน ส่งแล้วจะไม่ชวนอีกเลย

ในฟอร์มให้ดาว 1-5 กับแตะแท็กปัญหาที่เจอก็ส่งได้เลย ไม่ต้องพิมพ์ ส่วนจุดที่กำลังส่องอยู่
เวลาที่ใช้งาน และจำนวนจุดที่สแกน แอปแนบไปให้เองและแสดงให้ผู้ใช้เห็นก่อนกดส่ง

ถ้าตอนนั้นต่อ dashboard ไม่ได้ ทุกอย่างถูกเก็บไว้ในไฟล์ในเครื่อง (`usage-queue.jsonl`,
`feedback-queue.jsonl`) แล้วส่งให้เองเมื่อกลับมาออนไลน์ — ของที่ส่งสำเร็จเท่านั้นที่ถูกลบออกจากคิว
และทุก event มี id ประจำตัว เซิร์ฟเวอร์จึงไม่นับซ้ำแม้ส่งชุดเดิมใหม่

ดูผลได้ที่การ์ด "การใช้งานแอป AR" บนหน้าแดชบอร์ด หรือดาวน์โหลด CSV จากปุ่มในการ์ดนั้น

## ให้คนอื่นลองใช้ (ข้ามเน็ตเวิร์ก)

ค่าเริ่มต้นแอปคุยกับ dashboard ในวง Wi-Fi เดียวกัน ซึ่งใช้ได้เฉพาะตอนทดสอบเอง
พอจะแจกให้คนอื่นลอง เครื่องเขาอยู่คนละเน็ตเวิร์ก (เน็ตมือถือก็มี) จึงต้องมี URL สาธารณะ

วิธีที่ใช้อยู่คือเปิด tunnel จากเครื่องที่รัน dashboard ด้วย ngrok ที่จองชื่อโดเมนคงที่ไว้
(บัญชีฟรีจองได้ 1 ชื่อ) ชื่อจะได้ไม่เปลี่ยนทุกครั้งที่เปิดใหม่ จึงฝังลง APK ได้

```bash
ngrok config add-authtoken <authtoken ของบัญชีตัวเอง>   # ทำครั้งเดียว
ngrok http 3000 --domain <ชื่อที่จองไว้>.ngrok-free.app   # เปิดค้างไว้ตอนให้คนอื่นทดสอบ
```

เครื่องที่รัน dashboard ต้องเปิดและต่อเน็ตอยู่ตลอดช่วงนั้น เพราะข้อมูลทั้งหมด
(ค่าเซนเซอร์ CSV ของ Node-RED สถิติการใช้งาน) ยังอยู่ที่เครื่องนั้น

### token กันคนแปลกปลอมยิงข้อมูลเข้ามา

dashboard ไม่มีระบบล็อกอิน พอเปิดออกอินเทอร์เน็ตแล้วใครมี URL ก็ยิง feedback ปลอมได้
จึงให้แอปแนบ token มาด้วยทุกครั้งที่ส่งข้อมูล ตั้งที่ `.env.local` ของ dashboard:

```
AR_INGEST_TOKEN=<ค่าอะไรก็ได้ที่เดายาก>
```

แล้ว build APK ด้วยค่าเดียวกัน พร้อมฝัง URL สาธารณะไว้เลย ผู้ใช้จะได้ไม่ต้องกรอกเอง:

```bash
./gradlew :app:assembleDebug   -PdashboardUrl=https://<ชื่อที่จองไว้>.ngrok-free.app   -ParToken=<ค่าเดียวกับใน .env.local>
```

ไม่ตั้ง `AR_INGEST_TOKEN` = เซิร์ฟเวอร์ไม่ตรวจ ใช้งานในวง LAN ได้เหมือนเดิม
ตั้งแล้วแต่แอปไม่ได้แนบมา เซิร์ฟเวอร์ตอบ 401 และแอปจะ**เก็บข้อมูลไว้ส่งใหม่ ไม่ทิ้ง**
ส่วนการอ่านค่าเซนเซอร์ยังเปิดอยู่ เพราะหน้าเว็บกับแอปต้องใช้โดยไม่มี token

| popup ขึ้นแต่บอกว่ายังไม่มีข้อมูล | `deviceId` ใน `markers.json` ไม่ตรงกับอุปกรณ์ที่ส่งค่าเข้ามาจริง เทียบกับ `data/devices.json` |

### เจอมาแล้ว: ขาด HIGH_SAMPLING_RATE_SENSORS

อาการคือภาพจากกล้องขึ้นปกติแต่ไม่เจอรูป marker เลย และ log วนซ้ำว่า

```
กล้องยังไม่ TRACKING: PAUSED เหตุผล=NONE
```

พร้อมกับ log ของ ARCore เองที่บ่นว่า `IMU buffer is empty or has only one sample`

ตั้งแต่ Android 12 (API 31) แอปที่ไม่ประกาศ `android.permission.HIGH_SAMPLING_RATE_SENSORS`
จะอ่านเซนเซอร์ได้ไม่เกิน 200 Hz แต่ ARCore ต้องใช้ IMU ที่ 400-500 Hz
ระบบ VIO จึงเริ่มไม่ได้ กล้องค้างที่ `PAUSED` ตลอดและไม่ตรวจจับรูปเลย

แก้โดยประกาศใน `AndroidManifest.xml` (เป็น normal permission ระบบให้ตั้งแต่ตอนติดตั้ง ไม่มีหน้าต่างถาม)

```xml
<uses-permission android:name="android.permission.HIGH_SAMPLING_RATE_SENSORS" />
```

### อ่านสถานะการตรวจจับแบบเรียลไทม์

แอปพิมพ์สถานะวินาทีละครั้ง ใช้แยกได้ว่าติดที่ขั้นไหน

```bash
adb logcat -s ArSessionController
```

| ข้อความ | ความหมาย |
| --- | --- |
| `โหลด marker ได้ N รูป ใช้ไม่ได้ M รูป` | ผลการอ่าน `ar-markers/` ตอนเปิดแอป |
| `กล้องยังไม่ TRACKING: PAUSED เหตุผล=...` | motion tracking ยังไม่เริ่ม — `เหตุผล` บอกสาเหตุ (แสงน้อย ขยับเร็วไป ฯลฯ) |
| `กล้อง TRACKING แล้ว แต่ยังไม่เจอรูป marker` | ระบบพร้อม เหลือแค่เล็งให้ตรงรูป |
| `trackable=1 [dev-A.png TRACKING/FULL_TRACKING] popup=1 [...]` | เจอรูปแล้วและวาง popup ที่พิกัดบนจอเรียบร้อย |

ดู log ของฝั่ง AR ได้ด้วย

```bash
adb logcat -s ArSessionController MarkerCatalog SensorRepository
```
