# ar-markers — ArUco marker ของแอป AR

โฟลเดอร์นี้เก็บ **marker ที่ใช้พิมพ์ไปติดหน้างาน** ของแอป AR (`android-ar/`)
เมื่อกล้องอ่านรหัสได้ แอปจะเด้ง popup แสดงค่าเซนเซอร์ของอุปกรณ์ที่ผูกกับรหัสนั้น

marker เป็น **ArUco พจนานุกรม `DICT_4X4_50`** ถอดรหัสด้วย OpenCV ฝั่งแอป
สิ่งที่กล้องอ่านคือ **หมายเลข** (`arucoId`) ไม่ใช่ลวดลายของรูป ดังนั้นสองใบที่หมายเลขเดียวกัน
ถือเป็น marker เดียวกัน ไม่ว่าจะพิมพ์จากไฟล์ไหน

แอปอ่านโฟลเดอร์นี้โดยตรง — `android-ar/app/build.gradle.kts` ประกาศ
`assets.srcDirs += ../../ar-markers` ดังนั้นไฟล์ที่วางไว้ที่นี่จะถูกแพ็กเข้า APK ให้เอง

## ไฟล์ในโฟลเดอร์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `markers.json` | ผูก **arucoId → deviceId** (ขนาดพิมพ์ไม่ต้องระบุ) |
| `dev-*.png` `site-1.png` | รูปสำหรับพิมพ์ — ArUco ล้วน ไม่มีข้อความในภาพ |
| `generate_markers.py` | สร้างรูปใหม่จาก `markers.json` |

## เพิ่มอุปกรณ์ใหม่

1. เพิ่มรายการใน `markers.json` พร้อม **หมายเลขที่ยังไม่มีใครใช้**

   ```json
   { "image": "dev-G.png", "arucoId": 7, "deviceId": "dev-G", "label": "dev-G", "location": "โซน G" }
   ```

   - `arucoId` ต้องอยู่ในช่วง **0-49** และห้ามซ้ำ — ซ้ำเมื่อไหร่แอปจะโยนรายการหลังทิ้ง
     แล้วขึ้นเหตุผลไว้ในหน้า Settings
   - `deviceId` ต้องตรงกับ id ใน `data/devices.json` ของ dashboard (topic `sensors/<deviceId>/data`)
   - `widthMeters` **ไม่ต้องใส่ก็ได้** ใส่เมื่ออยากให้ popup บอกระยะเป็นเมตรเท่านั้น (ดูหัวข้อล่าง)
   - `kind` ใส่ได้สองค่า ถ้าไม่ใส่ถือว่าเป็น `sensor`

     | kind | หน้าต่างที่ขึ้น | เนื้อหาที่ใช้ |
     | --- | --- | --- |
     | `sensor` | คลิป + ข้อมูลจุดติดตั้ง + ค่าเซนเซอร์เรียลไทม์ | `ar-content/info/` `ar-content/video/` |
     | `history` | คลิป 360 องศา + ประวัติพื้นที่ (ไม่มีค่าเซนเซอร์) | `ar-content/history/` `ar-content/video360/` |

2. สร้างรูป

   ```bash
   python ar-markers/generate_markers.py            # สร้างใหม่ทั้งหมดตาม markers.json
   python ar-markers/generate_markers.py dev-G      # เฉพาะตัวที่ระบุ
   ```

   สคริปต์จะฟ้องทันทีถ้า `arucoId` ซ้ำหรือเกินช่วง

3. build แอปใหม่ แล้วพิมพ์ไปติด

## ข้อแนะนำตอนพิมพ์

**พิมพ์ขนาดไหนก็ได้** ไม่ต้องวัดให้ตรงค่าใด ๆ แอปอ่านจากรหัสในภาพ ไม่ได้อ่านจากขนาด
ArUco ต่างจากรูปทั่วไปตรงที่ "อ่านรหัส" ไม่ใช่ "จำลาย" ความคมของขอบจึงสำคัญที่สุด

- พิมพ์บนกระดาษ **ด้าน** ไม่เคลือบมัน — แสงสะท้อนทำให้ขอบดำแตก อ่านรหัสไม่ออก
- **ต้องเหลือขอบขาวรอบ ArUco** อย่างน้อยหนึ่งช่องตาราง (quiet zone) ในไฟล์เผื่อไว้ให้แล้ว
  แต่ถ้าสั่งพิมพ์แบบ "เต็มหน้า/ไม่มีขอบ" เครื่องพิมพ์อาจตัดขอบขาวทิ้งจนอ่านไม่ได้
- ติดบนพื้นผิวเรียบ ไม่ยับ ไม่โค้ง
- พิมพ์ขาวดำล้วนได้ ไม่ต้องใช้หมึกสี
- ในภาพไม่มีข้อความกำกับ ถ้าต้องแยกด้วยตาเปล่าให้เขียนกำกับข้าง ๆ เอาเอง (อย่าเขียนทับขอบขาว)

ยิ่งพิมพ์ใหญ่ยิ่งอ่านได้ไกลตามส่วน — วัดจากการทดสอบ marker ต้องกว้างราว **45 พิกเซล**
บนภาพกล้องจึงจะอ่านได้ครบ ซึ่งเท่ากับพิมพ์ 20 ซม. แล้วยืนห่างประมาณ 3.5 เมตร
อยากได้ไกลเป็นสองเท่าก็พิมพ์ใหญ่เป็นสองเท่า

### อยากให้ popup บอกระยะเป็นเมตร

ต้องบอกแอปว่าพิมพ์กว้างเท่าไร เพราะภาพอย่างเดียวแยกไม่ออกว่าเป็นใบเล็กที่อยู่ใกล้
หรือใบใหญ่ที่อยู่ไกล — ใส่ `widthMeters` (ความกว้างของ **ขอบดำด้านนอก** เป็นเมตร)
ในรายการนั้น หรือใส่ `defaultWidthMeters` ไว้ระดับบนสุดถ้าพิมพ์ทุกใบเท่ากัน

```json
{ "version": 1, "defaultWidthMeters": 0.2, "markers": [ ... ] }
```

ไม่ใส่ก็ใช้งานได้ปกติทุกอย่าง แค่ไม่มีตัวเลขเมตรใต้ชื่อจุด และการเลือกว่า "ใบไหนใกล้สุด"
จะดูจากขนาดบนจอแทน (ถูกเสมอถ้าพิมพ์ทุกใบขนาดเท่ากัน)

## ทำไมไม่ใช้ Augmented Images ของ ARCore

ของเดิมใช้รูปลวดลายสุ่มป้อนเข้า `AugmentedImageDatabase` ซึ่งต้องการรูปที่มี feature เยอะ
กระจายทั่วภาพ ส่วน ArUco เป็นสี่เหลี่ยมขาวดำที่แทบไม่มี feature เลย ARCore จะปฏิเสธ
(`ImageInsufficientQualityException`) หรือรับแล้ว track ไม่ติด

ย้ายมาอ่านเองด้วย OpenCV แล้วได้ข้อดีติดมาด้วย

- เจอทันทีในเฟรมเดียว ไม่ต้องรอ ARCore สร้าง map ของฉากก่อน
- ทำงานได้แม้ ARCore ยังไม่ TRACKING (ห้องมืดหรือผนังเรียบ ๆ ที่หา feature ไม่ได้)
- เพิ่ม marker ใหม่ไม่ต้องห่วงเรื่องคุณภาพรูป ขอแค่หมายเลขไม่ซ้ำ
- พิมพ์ขาวดำใบเล็ก ๆ ก็ใช้ได้

แลกกับ APK ที่ใหญ่ขึ้นราว 36 MB จาก native library ของ OpenCV
